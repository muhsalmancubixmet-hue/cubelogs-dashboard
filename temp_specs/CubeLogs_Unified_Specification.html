CubeLogs — Project Core Specifications

Simplified Functional Requirements Documentation

1. Unified Login Screen

The application implements a single, unified login screen shared by the Super Admin and all regular employees.

  • Login Flow: When a user enters their email and password, the system checks their role. If the user is the Super Admin, they are redirected to a dashboard with full system controls. Regular employees are redirected to their assigned workspace layout.
  • Super Admin Privilege: The Super Admin has absolute access to every page, feature, and sub-menu option in the entire system.

2. Master Role Template Engine

To keep configuration quick and efficient, the Super Admin can pre-define standard baseline permissions for different organizational titles before onboarding individual employees.

  • Core Mechanisms: When creating a new role template (e.g., HR, Developer, Cleaning Staff), the Admin selects which specific pages they can view. A master global checkbox toggle ("Select All") is included to instantly check or uncheck all permission flags with a single click.

3. Employee Creation & Custom Overrides

When the Super Admin onboards a new worker under /admin/employees/create, the setup is processed in two clean steps on the same screen:

Step 1: Core Personal Data & Designation

The Admin populates basic identification records: Full Name, Email, Phone Number, and selects the exact Designation from a dropdown list (which directly links to the Master Role Templates).

Step 2: Default Template or Live Custom Override

Selecting a Designation instantly loads its preset template permissions right on the screen. Below this configuration, an active checkbox handles the authorization logic:

  • "Use default page permissions for this profile" Checkbox: This option is checked by default. If left checked, the nested checkboxes remain read-only, allowing the Admin to save the profile in under 5 seconds.
  • The Custom Override Option: If the Admin unchecks this box, the permission matrix instantly unlocks on the exact same screen. The Admin can freely customize, add, or remove page access for this specific user without altering the original master role template rules.
A Simple Real-World Example:
1. The Admin selects Designation: "Cleaning Staff". The system automatically selects only the Clock-In/Out page as active, leaving all other features turned off.
2. For Standard Staff: The Admin leaves the default permissions checkbox ticked and saves the profile immediately.
3. For a Special Case Staff: If a specific cleaning staff member also needs access to view the Holiday Calendar, the Admin simply unticks the default checkbox. The permission checklist unlocks instantly on the spot, allowing the Admin to check the Holiday Calendar page just for this individual.

4. Hierarchical Sidebar Structure (Dropdown Menus)

To keep the interface clean and structured, the sidebar utilizes an expandable dynamic accordion/dropdown menu architecture. Clicking on a primary category expands a nested tree of sub-pages based on user permissions. The Super Admin uniquely views all existing nested items simultaneously.

4.1 Tasks Dropdown Module

Clicking the primary "Tasks" category triggers a dynamic dropdown containing two separate operational sub-pages:

  • Add Task Workspace: Dedicated space for the Super Admin, Human Resources, or Senior Staff to create, schedule, and assign new tasks to specific developers or teams.
  • My Tasks View: A personal workspace interface for regular developers and staff members to track their individually assigned project objectives.
  • Role Restriction: Super Admin simultaneously views and operates both sub-pages within their dropdown workspace. Developers only see and access the "My Tasks View" node.

4.2 Leave Management Dropdown Module

Clicking the primary "Leaves" category opens an expandable dynamic sub-menu containing two operational nodes:

  • Apply Leave Form: A self-service interface dedicated to developers, cleaning staff, and regular employees to file new time-off requests.
  • Leave Approval Portal: A management control dashboard utilized by HR and upper administration to review, approve, or reject active employee leave requests.
  • Role Restriction: The Super Admin retains structural visibility of both sub-menus simultaneously. Standard staff are strictly confined to the "Apply Leave Form" sub-page.

4.3 Holiday Calendar Dropdown Module

Clicking the primary "Holidays" category expands into structural sub-directories based on user permission matrices:

  • Configure System Holidays: A full CRUD workspace enabling administration to provision, edit, or remove national or corporate calendar closures.
  • View Holiday Calendar: An interactive, read-only calendar framework displaying upcoming corporate events for regular developers and workforce staff.
  • Role Restriction: The Super Admin views and handles both operational pages concurrently. Regular staff view the calendar only.

4.4 Attendance & Clocking Monitor

  • Staff View: If permitted, employees see clear actions for Clock-In, Clock-Out, Break Start, and Break End. Their total active shift duration updates and renders live on their screen.
  • Admin View: A live synchronized table maps the active punch-in status of all personnel. Clicking on a name triggers an overlay showing their profile summary, full log history, and assigned tasks. The Admin holds master override credentials to manually adjust time logs.
